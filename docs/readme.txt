# Dify 文档可视化AI工作流 Demo
> AI产品经理实战项目，基于Dify低代码平台搭建文档自动解析+数据可视化工作流。

## 📌 项目简介
**项目背景**：业务人员需要快速将非结构化文档（Excel/文本报表）自动提取数据、清洗规整并生成ECharts可视化图表，无需手动写代码。
**角色定位**：AI产品经理，负责需求分析、流程设计、节点编排、测试验证、方案落地。

### ✅ 工作流链路（当前实现）
`开始(上传文件)` → 文档提取器 → LLM数据格式化 → 代码节点生成ECharts图表 → 输出可视化结果
1. 文档提取器：读取上传文档内原始销售数据
2. LLM节点：基于DeepSeek模型清洗、规整、结构化原始数据
3. 代码节点：自动生成ECharts前端图表代码，输出可视化柱状图
4. 输出：直接返回可渲染的图表，实现**上传文档一键出图表**

## 🧩 项目能力
- 支持上传报表文件，自动提取文档内非结构化业务数据
- 大模型做数据清洗、字段对齐、异常值简易处理
- 代码节点自动生成ECharts图表，输出可视化结果
- 工作流可复用，更换数据源即可生成不同业务图表

## 📂 仓库文件说明
- `visual-data-workflow.yml`：Dify工作流DSL配置文件，可直接导入Dify复现完整流程
- `docs/`：项目PRD、需求分析、产品复盘文档
- `screenshot/`：画布截图、测试运行效果图

## 🔧 复现方式
1. 本地部署Dify（Docker）
2. 新建应用，选择【导入DSL】，上传本仓库yml文件
3. 配置模型密钥（DeepSeek），即可运行测试

## 💡 产品思考（面试可讲）
1. 痛点：业务人员不会写ECharts、手动整理报表耗时，重复工作多
2. 方案选型：低代码AI工作流，不用开发前端，快速交付最小可用产品
3. 局限：大模型存在数据解析误差，需增加校验分支；大文件稳定性有待优化
4. 迭代方向：增加数据校验节点、支持更多图表类型、增加多文件批量处理
